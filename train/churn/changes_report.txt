============================================================
  CHURN PIPELINE FIX REPORT
  Date: 2026-06-05
============================================================

OBJECTIVE
---------
Align churn training pipeline files with the actual CSV data
so that FEB2026 is the reference (start) month and MAY2026
is the target month.

ROOT CAUSE
----------
Column names in config.py did not match the columns present
in the real CSV files:
  - Prime CSVs use "RIM_NO" as the customer identifier,
    but config referenced "CUSTOMER_ID".
  - Transaction CSVs have a fake sequential "CUSTOMER_ID"
    column (1, 2, 3, ...) and the real customer ID lives in
    a column called "RIMNO".
  - Several other column names had typos or spacing
    mismatches vs. the actual data headers.

============================================================
  FILE: config.py
============================================================

1) Added customer-ID mapping constants
   OLD:  CUSTOMER_ID = "CUSTOMER_ID"
   NEW:  CUSTOMER_ID = "CUSTOMER_ID"          # internal name
         PRIME_CUSTOMER_ID_RAW = "RIM_NO"     # prime CSVs
         TXN_CUSTOMER_ID_RAW   = "RIMNO"      # transaction CSVs

2) Fixed month comments (were stale / wrong)
   OLD:  CHURN_REFERENCE_MONTH = "202602"  # JUL 2025
         CHURN_TARGET_MONTH    = "202605"  # FEB 2026
   NEW:  CHURN_REFERENCE_MONTH = "202602"  # FEB 2026 -- base cohort
         CHURN_TARGET_MONTH    = "202605"  # MAY 2026 -- check presence

3) Fixed transaction column names to match actual headers
   OLD:  TXN_DATE_COL     = "TRXN_DATE"
         TXN_REVERSAL_COL = "REVERRSAL FLAG"
   NEW:  TXN_DATE_COL     = "TRXN DATE"       (space, not underscore)
         TXN_REVERSAL_COL = "REVERSAL FLAG"    (single R, not double)

4) Fixed prime feature column names
   OLD:  "AVILABLE_LIMIT"  ->  NEW: "AVAILABLE_LIMIT"
   OLD:  "STATUS_NAME"     ->  NEW: "STATUS_NAME"
   (These match the actual typos present in the raw data.)

5) Fixed CATEGORICAL_COLS to match
   OLD:  "STATUS_NAME"     ->  NEW: "STATUS_NAME"

============================================================
  FILE: data_loader.py
============================================================

1) _load_label_file()  -- RIM_NO -> CUSTOMER_ID mapping
   Previously loaded only columns that exactly matched
   the requested names, so "CUSTOMER_ID" was never found
   in prime CSVs (they use "RIM_NO").

   Now resolves requested column names against file headers:
     - If "CUSTOMER_ID" is requested but absent, checks for
       "RIM_NO" instead and renames it after loading.

2) load_transaction_data()  -- RIMNO -> CUSTOMER_ID mapping
   Transaction CSVs contain two ID columns:
     "CUSTOMER_ID" = fake sequential integer (1, 2, 3, ...)
     "RIMNO"       = real customer ID matching prime RIM_NO

   Added logic to:
     a) Drop the fake "CUSTOMER_ID" column
     b) Rename "RIMNO" to "CUSTOMER_ID"
   This ensures downstream merges join on the correct key.

3) load_prime_data()  -- RIM_NO -> CUSTOMER_ID rename
   After loading each prime CSV, renames "RIM_NO" to
   "CUSTOMER_ID" so the rest of the pipeline uses a
   consistent column name.

4) Fixed Unicode encoding crash
   OLD:  print(f"  Churn Labeling -- {ref_key} -> {tgt_key}")
         (contained Unicode em-dash and arrow characters)
   NEW:  Uses plain ASCII characters only.
         Windows cp1252 console could not encode the Unicode
         arrow U+2192, causing a UnicodeEncodeError crash.
